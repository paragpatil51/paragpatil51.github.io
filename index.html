QPulse Global Threat Pulse · cyber threat intelligence

A cyber threat-intelligence platform that reads the security news so analysts don't have to. Every article from global and Indian feeds is turned by an LLM into structured, ranked intelligence, then translated and emailed to the people who need it.

  • LLM as a structured extractor. Gemma-3-27B at temperature 0.1 returns one strict JSON per article: severity, a 1–10 industry risk score with justification, executive summary, kill-chain analysis, MITRE ATT&CK TTPs, CVEs, IOCs, detection ideas and recommendations.
  • Token budget as a design input. Content is trimmed before the call, URLs are de-duplicated so nothing is analysed twice, work runs in batches of 20 with cooldowns, and a limiter holds translation to 60 RPM / 15k TPM.
  • Reaches people in their language. Articles are machine-translated into 7 Indian regional languages, and subscribers get personalised daily digests, including a Regulator Watch for RBI and CERT-In.
  • Hardened for the open internet. Tiered rate limits, reCAPTCHA v3, security-headers middleware, trusted hosts and masked validation errors.

QStellar AI Multi-agent assistant & document RAG

An AI-powered cyber risk intelligence platform. I worked on its AI assistant, built the specialist agents, and built the document RAG pipeline that lets analysts question their own security reports, with answers that cite sources and are checked against live platform data. I also built the React + TypeScript frontend these features live in.

  • Agents that know when not to use an LLM. A router sends factual questions ("how many critical CVEs?") straight to SQL for exact answers, and only analytical ones to the Asset, Vulnerability, Threat and Executive agents, which run in parallel under 8s / 18s SLA timeouts.
  • Grounded before it's shown. A grounding layer checks the synthesised answer against the database (CVE IDs exist, counts and severities match), with a scope guard in front and a circuit breaker behind.
  • RAG tuned per file type. LangChain loaders for PDF, DOCX, CSV and Excel; different chunk sizes for prose, PDFs and tables; BGE-small embeddings; a ChromaDB collection per user so documents never leak between tenants.
  • Private by default. Answers come from Qwen2-7B served locally through Ollama, so sensitive reports never leave the network.

QDetect ML-driven SOC alert triage · QStellar module

Security teams drown in alerts. QDetect is the QStellar module I designed and built on my own: it connects to a live Wazuh SIEM, learns which alerts are noise and which are real, and turns what's left into a 0–100 security score per asset.

  • Measured on real data. Over 83,321 production alerts, a rule-based pass flagged 70,336 (about 84%) as noise, with guardrails that never suppress MITRE-mapped, level ≥ 12, ransomware or endpoint-agent signals.
  • Four models for the grey zone. The ~12k alerts left over are scored by an ensemble of Isolation Forest, DBSCAN, Random Forest and a KNN / rule-family classifier, with a low-sample fallback so rare rules aren't ignored.
  • Humans stay in charge. Suggested suppression rules go through approve / reject / revert, and feature importances explain each score.
  • Full integration. Wazuh REST API + OpenSearch indexer, scheduled sync of agents, alerts, vulnerabilities and CISA KEV into PostgreSQL, all served through 80+ FastAPI endpoints.

06~/parag/system_prompt.md

Principles I've learned from production, not tutorials.

systemYou are Parag, an engineer shipping LLM features to real users. Before writing any code, follow these four rules.

i.

Ground before you generate

If the answer lives in a database, query the database. I route factual questions to SQL, save the LLM for reasoning, and check its output against real data before anyone sees it.

ii.

Tokens are a budget

Trimming inputs, de-duplicating before the call, batching, and schedulers that respect rate limits. Cost and latency are product features, so I design for them from day one.

iii.

Private by default

When data can't leave the network, the model comes to the data: local LLMs through Ollama, and per-user vector collections so one tenant's documents never reach another's answers.

iv.

The harness is the product

Scope guards, rate limits, circuit breakers and audit trails go in the first version. The model is one component; the system around it decides whether it can be trusted.
